## 1. Resumen Ejecutivo

Se requiere desarrollar una aplicación web para un gimnasio de entrenamiento personalizado que permita gestionar hasta **100 clientes activos**, registrando sus avances físicos, nutricionales, emocionales y de rendimiento en el entrenamiento. La plataforma debe generar **evaluaciones automáticas cada 21 días** con gráficos comparativos y mantener una **base de datos independiente por alumno**.

### Objetivos Principales
- Centralizar toda la información de cada cliente en un perfil único e independiente.
- Automatizar la creación de evaluaciones periódicas (cada 21 días).
- Visualizar el progreso mediante gráficos interactivos.
- Facilitar el seguimiento de asistencia, rutinas, alimentación y estado de ánimo.
- Generar reportes cuantificables del tiempo total de entrenamiento.

Schema::create('clients', function (Blueprint $table) {
    $table->id();
    $table->string('name', 100);
    $table->string('email', 100)->unique();
    $table->string('phone', 20)->nullable();
    $table->date('birth_date');
    $table->enum('gender', ['male', 'female', 'other']);

    $table->foreignId('trainer_id')->constrained('users');
    $table->timestamps();
    $table->softDeletes();
});

## 8. Stack Tecnológico — Laravel Ecosystem

### 🟠 Núcleo del Sistema

| Capa | Tecnología | Versión | Justificación |
|---|---|---|---|
| **Framework** | Laravel | 11.x+ | Framework PHP más robusto, ecosistema maduro, comunidad activa |
| **Lenguaje** | PHP | 8.2+ | Tipado fuerte, atributos, performance mejorada |
| **Servidor Web** | Nginx | Última | Más rápido que Apache para aplicaciones modernas |

### 🟢 Frontend

| Tecnología | Propósito | Justificación |
|---|---|---|
| **Blade** | Motor de plantillas nativo de Laravel | Sintaxis limpia, herencia de layouts, componentes |
| **Livewire** | Componentes dinámicos sin escribir JavaScript | Ideal para formularios en tiempo real, tablas interactivas, modales |
| **Alpine.js** | JavaScript minimalista para interacciones ligeras | Complementa Livewire para dropdowns, toggles, tooltips |
| **Tailwind CSS** | Framework CSS utility-first | Desarrollo rápido de UI, diseño consistente, responsive |
| **ApexCharts.js** | Gráficos interactivos y responsivos | Mejor rendimiento que Chart.js para grandes volúmenes de datos |
| **FullCalendar.js** | Calendario de asistencia y entrenamientos | Vista mensual/semanal de sesiones |

### 🔵 Backend & Base de Datos

| Tecnología | Propósito | Justificación |
|---|---|---|
| **MySQL 8.0+** / **MariaDB 10.6+** | Base de datos relacional | Compatible, robusta, gratuita, ideal para datos estructurados |
| **Eloquent ORM** | ORM nativo de Laravel | Relaciones fluidas, eager loading, mutadores, scopes |
| **Laravel Migrations** | Control de versiones de la BD | Evolución controlada del esquema, rollback seguro |
| **Laravel Seeders** | Datos de prueba | Población rápida de la BD para desarrollo y demos |
| **Laravel Factories** | Generación de datos falsos | Testing y desarrollo con datos realistas |

### 🟣 Autenticación y Seguridad

| Tecnología | Propósito | Justificación |
|---|---|---|
| **Laravel Breeze** | Starter kit de autenticación | Login, registro, recuperación de contraseña, verificación de email |
| **Laravel Sanctum** | Autenticación API (futuro) | Si en el futuro se necesita app móvil |
| **Laravel Policies** | Control de acceso por recursos | Un entrenador solo ve sus clientes |
| **Laravel Encryption** | Encriptación de datos sensibles | Nativo, AES-256 |
| **Laravel Hashing** | Contraseñas seguras | Bcrypt por defecto |

### 🔴 Procesamiento en Segundo Plano

| Tecnología | Propósito | Justificación |
|---|---|---|
| **Laravel Queue** | Colas de trabajo asíncronas | Generación de PDFs, envío de emails, procesamiento de imágenes sin bloquear la app |
| **Redis** | Driver de colas + Cache + Sesiones | Ultra rápido, reduce carga de la BD |
| **Laravel Scheduler** | Tareas programadas (cron) | Evaluaciones automáticas cada 21 días, backups diarios, alertas |
| **Supervisor** | Gestión de workers de cola | Mantiene los workers corriendo 24/7 |

### 🟡 Almacenamiento y Archivos

| Tecnología | Propósito | Justificación |
|---|---|---|
| **Laravel Storage** | Abstracción de almacenamiento de archivos | Cambiar entre local, S3, etc. sin modificar código |
| **Intervention Image** | Procesamiento de imágenes | Redimensionar fotos corporales, compresión, watermark |
| **AWS S3 / MinIO** / **Local** | Almacenamiento de fotos y PDFs | Escalable, seguro, con CDN opcional |

### 🟤 Reportes y Exportación

| Tecnología | Propósito | Justificación |
|---|---|---|
| **Laravel DomPDF** | Generación de PDFs | Reportes de evaluación en PDF directamente desde HTML/Blade |

| **Laravel Snappy / Browsershot** | PDFs con alta fidelidad | Alternativa si DomPDF no renderiza bien los gráficos |

### ⚪ Búsqueda y Notificaciones

## 12. Preguntas Abiertas para el Cliente

Para afinar el alcance y priorizar funcionalidades, sería útil conocer:

### Sobre el Alcance y Uso
1. **¿La aplicación será usada únicamente por entrenadores/administradores, o también los clientes tendrán acceso para ver su progreso?**
   - Respuesta: entrenadores/administradores y clientes para su progreso
   - Esto afecta la arquitectura de roles (Laravel Policies) y si se necesita Laravel Sanctum para API móvil.

2. **¿Se necesita versión móvil (app nativa) o basta con la web responsive?**
   - Respuesta: aplicacion web responsive
   - Los entrenadores suelen usar tablets en el gimnasio. Si se necesita app móvil, Laravel Sanctum es esencial.

3. **¿Los 100 clientes son simultáneos o es el total histórico? ¿Hay rotación?**
   - Respuesta: sin limite de clientes es el total que actualmente se gestiona
   - Importante para el diseño de la base de datos, soft deletes y límites de licencia.

### Sobre Datos y Métricas

4. **¿El cálculo de BMI, edad metabólica y Kcal basal se hace manualmente o se ingresan directamente desde un equipo (báscula bioimpedancia)?**
   los datos edad metabólica, kg, BMI, Kcal bases son tomados con una pesa inteligente de INbody con la que se evalúan a cada alumno donde entrega cada dato al ser utilizado. 
   - Si hay integración con equipos, se necesita investigar APIs o importación de archivos CSV.

5. **¿Las fotos corporales se toman en posiciones específicas (ropa, fondo, iluminación) o son libres?**
   - Respuesta: las fotos son tomadas 4 poses, pose de frente, espalda, lado izquierdo y lado derecho, por el alumno en su casa está deben ser tomadas en traje de baño 
   - Afecta la funcionalidad de guía para fotos consistentes y posible procesamiento con Intervention Image.

6. **¿Las evaluaciones de 21 días son fijas desde la fecha de inicio de cada cliente, o hay evaluaciones generales para todos?**
    - Respuesta: las evaluaciones están sujetas cuando el alumno inicia desde el Primer control desde ahí en adelante se coloca un plazo de 21 dias cómo minino  
   - Cada cliente tiene su propio ciclo de 21 días desde su inicio (ya contemplado en el diseño).

### Sobre Rutinas y Ejercicios
7. **¿Las rutinas son creadas por ustedes o usan alguna base de ejercicios predefinida?**
   - Respuesta: las rutinas son creadas y estandarizadas por un periodo de 3 meses de duración donde cada alumno según sus días de entrenamiento con el plan que tienen de clases por semana van realizando cada semana de manera periódica se dirigen con entrenador disponible
   - Se puede crear una biblioteca reutilizable de ejercicios (seeders con datos iniciales).

8. **¿Necesitan registro de ejercicios en tiempo real durante la sesión o se cargan al final?**
   - Respuesta: El peso se anota segun la primera serie de cada ejercicio el base con el inicia las primera 15 repeticiones y el último peso sería el 3 serie y final que es la serie que es  efectiva donde se busca sumar el peso máximo a lograr para 8 a 10 repeticiones de cada ejercicio según la rutina que le toque 
   - Afecta la UX de Livewire (formularios rápidos vs. formularios extensos).

### Sobre Presupuesto y Despliegue
9. **¿Tienen preferencia por alojamiento propio (servidor local/VPS) o en la nube (AWS, DigitalOcean)?**
   - Respuesta: alojamiento propio de bajo costo. Railway, hosting o herramienta para desplegar rapido 
   - Afecta costos, mantenimiento y si se usa Laravel Forge/Ploi o configuración manual.

10. **¿Necesitan integración con alguna herramienta existente (calendario Google, WhatsApp Business, email SMTP propio)?**
	- Integraciones como, calendario de google, WhatsApp, correos electronicos
    - Laravel Notifications soporta múltiples canales: email, SMS, Slack, webhooks.
